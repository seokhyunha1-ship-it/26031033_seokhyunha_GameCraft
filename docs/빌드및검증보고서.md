# 빌드 및 검증 보고서

검증일: 2026-10-25

## 실제 실행한 검증

- 기존 솔루션 Release / net9.0-windows 빌드: 경고0, 오류0. SDK10.0.401, 설치된 기존 패키지로 빌드.
- `--self-test`: 30/30 통과. 세부 결과는 self-test-results.txt. 충전·게이지·50m 도약·방향 저장·물 색상·동시/순차 접촉·패링·일반 피격·아이템·최고 높이·보너스·재시작·개별 사망·생성 간격 검사.
- 600초 상당 고정시간 시뮬레이션으로 플랫폼/아이템/불 객체 수 상한 검사. 실시간10분 사람이 플레이한 검증은 아니다.
- `--asset-check`: PNG99개 모두 실제 Direct2D 텍스처 생성 성공. asset-check-results.txt 참고. 기본 WAV17개도 AudioManager에서 정상 초기화, 오디오 오류 로그 없음.
- 실제 게임 창에서 타이틀과 조작 안내가 온전히 표시되는 것을 확인. 초기 DPI 배율에 의한 하단 잘림 발견 후96DPI 렌더링으로 수정.
- 실제 창에서 구간3의 게임 오버, 현재 점수1809·기존 최고3149, 캐릭터별 최고 높이 표시를 확인. 자동 플레이가 아니라 창에서 관찰한 결과이며 모든 구간 완주 검증은 아니다.
- PNG 알파 채널 및 해상도 전수 검사. 원본99개 수정 없음. 배경은 불투명, 투명 sprite는 실제 알파 픽셀이 존재한다.

## 코드로 확인한 범위

- Pause/Results에서는 시뮬레이션 호출을 하지 않아 오리·발사 쿨타임·점수가 정지한다. 복귀 시 충전 입력을 정리한다. 별도 오디오 Pause/Resume 제공.
- 배경3~6의 순환/전환 이미지 연결, 실제 최고높이와 카메라 분리.
- BGM 루프·음량 혼합과 효과음 동시 재생 구조. 실제 청취 품질 평가는 수행하지 않았다.
- 최고기록 저장 경로와 오류 로그, 재시작 초기화.
- 캐시 최대28텍스처 및 과거 객체 제거. 실행 프로세스의 지속 메모리 그래프는 계측하지 않았다.

## 남은 검증과 알려진 제한

1. 사람2명이 모든 고도 구간을 장시간 플레이하면서 난이도·키보드 동시입력·회복률을 조정해야 한다. 생성기의 간격/겹침은 검사했으나 모든 실수 상황에서 탈출 경로를 보장하는 것은 아니다.
2. VS2022 GUI에서 프로젝트 다시 열기/빌드 버튼은 직접 검증하지 않았다. 기존 .sln/.csproj를 사용했고 CLI 솔루션 빌드는 성공했다.
3. `배경6.png`가 없어 예시1로 대체. 새 그림이 필수는 아니지만 별도 기본 우주 배경을 원하면 추가 가능하다.
4. 제공 MP310개의 원저작자·URL·라이선스는 미확인. 기본 실행은 자체 WAV를 사용한다. 원음을 사용하려면 증빙 확인 후 설정 전환.
5. 배경의 별/구름은 원본 이미지 안에 포함되어 있다. 개별 별·구름 무작위 입자는 구현하지 않았다.
6. 충돌은 고정120Hz의 중심점/범위 판정이다. 플랫폼 색상 접촉 순서는 선분 진입 시간을 사용하지만 모든 투사체가 픽셀 단위 충돌인 것은 아니다.
7. 패링 성공/피격/발사는 별도 합성음, 먹힘·색변경·구간전환·기록갱신 전용음은 늘리지 않았다. 기존 이벤트음/게임오버음/BGM 전환으로 대응한다.
8. 원본의 옅은 외곽광과 질감은 보존했다. 모든99개의 모든 장면 조합을 육안 대조하지는 않았다.

## 재현

Release 실행 파일에 --self-test / --asset-check를 각각 붙여 실행한다. JSON Seed를 정수로 바꾸면 같은 플랫폼 생성열을 얻는다. 무입력 패링 방향은 위다. 일반 점프 방향은 누른 다음 갱신에 저장한다.

제출 전 권장 순서: 2인 플레이 감각 조정 → 모든 배경 전환 직접 확인 → 소리 청취/음량 조정 → 학교 PC의 .NET9 Desktop Runtime 및 VS 확인.

최종 보완 중 기존 Release 실행 파일이 열려 덮어쓰기 빌드가 한 차례 실패했다. 코드 오류가 아니라 파일 사용 중 잠금이었다. 열린 게임은 유지하고 `bin/ReleaseVerified`로 출력하여 경고0/오류0 빌드 및30개 테스트를 다시 통과했다. 이 폴더가 최종 검증본이다.
