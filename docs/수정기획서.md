## 1. 목적과 적용 기준

래피와 블피가 계속 상승하는 오리를 피해 물 플랫폼을 타고 올라가는 2인 협력 게임으로 발전시킨다. 점프 게이지 관리, 팔딱을 통한 순간 방향 전환, 물 색 변경을 통한 협력, 패링과 수둔을 통한 위기 탈출이 핵심이다. 공격으로 오리를 처치하는 클리어 방식은 두지 않는다.

이 문서는 오늘의 사용자 요청과 최종 코드·설정을 대조해 정리한 **현재 게임 설계 명세**다. 과거 v0.1/v0.2의 제안과 중간 조정값을 현재 규칙처럼 병기하지 않는다. 사용자가 직접 지정한 값과 구현 과정에서 정한 조정값은 구분하며, 후자는 플레이 결과에 따라 재조정할 수 있다.

- 최종 사용자 지정: **오리 기본 속도165**, 불 피격 스턴0.3초.
- 현재 적용 조정값: 구간당 오리 속도+3, 불 속도360, 공격 주기5초·정지0.50초, 수둔 스턴1.2초 등 아래 표의 값.
- 작업 근거: 현재 `game-settings.json`, 게임 코드, 실제 리소스 폴더, 오늘의 사용자 요청 및 최종 실행 검사 기록.
- 상세 리소스는 [resource_list.md](../resource/resource_list.md), 구현·검증 이력은 [구현및검증서.md](구현및검증서.md)에서 관리한다.
- 오늘 참고한 세로 스크롤 영상은 다른 게임의 흐름 참고 자료다. Jumping Fish의 실제 플레이 문제를 관찰한 영상으로 혼동하지 않는다.

## 4. 조작과 협력 규칙

| 행동 | 래피(P1) | 블피(P2) |
|---|---|---|
| 헤엄·공중 방향 | WASD | 방향키 |
| 충전·일반 점프 | Space 누르기·떼기 | ] 누르기·떼기 |
| 공중 팔딱 | 방향+Space 새로 누르기 | 방향+] 새로 누르기 |
| 패링 | Space, 공용키 분기 적용 | Enter 단독, ] 공용키 분기 적용 |
| 일시정지 | ESC | 공통 |

- 래피는 파란 물에 들어가 빨강으로, 블피는 빨간 물에 들어가 파랑으로 바꾼다. 자기 색 물에 공중 진입하면 기존 거부·추락 제한을 적용한다.
- 먼저 올라갈 수 있는 사람이 물 색을 바꾼 뒤 다른 사람이 따라간다. 높은 추격 속도에서는 동료가 도착한 다음 충전을 시작하기보다 두 사람이 미리 준비하는 협력이 중요하다.
- 두 사람이 같은 물 안에 머물면 색이 다시 바뀌어도 양쪽 모두 수영으로 회복할 수 있다. 혼자 불리한 색 물에서 수영하면 기존 감소 규칙을 적용한다.
- 게이지가 있으면 물속 대기·충전 중 중력과 부력이 균형을 이루고 남은 수직 움직임이 감쇠한다. 게이지가 없으면 가라앉는다. 물 안에서도 올라오는 위험 경계를 피해야 한다.
- 일반 점프 방향 편향은 유지한다. 충전 중 위+좌/우를 누른 시간에 비례해1초에 최대±30도로 조절한다. 물에서 벗어나면 충전을 취소한다.
- 한 명이 탈락해도 살아 있는 플레이어는 계속 진행하며, 두 명 모두 탈락하면 게임 오버다.

## 5. 맵·카메라·물 플랫폼

### 화면과 스크롤

플레이어의 높은 점프가 카메라를 갑자기 끌어올리지 않는다. 오리의 실제 상승량만큼 카메라가 함께 상승한다. 공격 정지와 수둔 스턴 때는 카메라도 멈춘다. 캐릭터가 상단 밖으로 올라가 경로를 건너뛰지 않도록 상단 경계를 둔다. 점수는 상단 물의 색을 가리지 않게 배경 패널 없이 숫자로 표시한다.

### 플랫폼 생성

- 세계 폭2068, 좌우 여백40. 시작 물은 전폭이며 높이180이다.
- 주 경로 폭은 소형130~210, 중형250~360, 대형430~570이며 높이도80~260 범위에서 구분해 뽑는다.
- 주 경로 간 수평 겹침60 이상을 확보한다. 위아래 물 표면 사이 간격은120~200이다.
- 좌우 분기 물은 한 생성 묶음에서 각 측면 최대1개이며 공간·분리·연결 조건을 만족할 때만 생성한다. 가로 간격80, 세로 위치 변동±90을 사용해 고정 행·열처럼 반복되지 않게 한다.
- 과거의 ‘가로20개·세계 폭4136·1920×1080’은 현재 기준이 아니다. 실제 한 화면의 물 개수는 크기·간격·스크롤 위치에 따라 달라지며 고정 개수로 보장하지 않는다.
- 화면 전체의 **생성 색**이 한쪽으로 치우치지 않도록 높이순으로 빨강/파랑을 교대 배정한다. 화면 안에 중심이 들어온 물이2개 이상이면30:70~70:30 범위가 되도록 한다.0~1개인 경우는 비율 적용에서 제외한다.
- 입수로 바뀌는 현재 색은 플레이 결과다. 생성 비율을 맞추기 위해 이미 등장한 물의 현재 색을 강제로 되돌리지 않는다.

## 6. 일반 점프와 팔딱의 자원 도전

일반 점프는 높이를 확보하고 팔딱은 공중에서 순간적으로 방향을 틀거나 부족한 이동을 보완한다. 팔딱은8방향 입력을 정규화한 뒤 기존 속도를 교체하며, 유효 방향이 있으면 패링 대기 없이 발동한다. 방향을 먼저 누르고 있어도 허용한다. 점프키를 먼저 눌렀는데 방향이 없을 때만 최대0.30초 기다린다.

일반 점프 실제 비용을 J라고 하면 팔딱 비용은 `J×0.25`, 속도는 `min(480, 1.6×sqrt(300×J×0.7×10))`이다. 비용과 속도 계산은 분리한다. 예를 들어 점프40이면 팔딱10이며, 최대 점프75와 팔딱18.75를 함께 쓰면93.75를 소비한다. 실제 비행 거리 소모와 피격은 별도다.

0.18초 직진 뒤 일반 중력·공중 조절을 재개한다. 수평 초과 속도는 점진적으로 줄이고 상승 초과 속도에도 추가 감속을 적용한다. 벽·물·불·사망 판정은 직진 중에도 처리한다. 일반 점프당1회이며 패링 무료 도약·자기 색 물 거부 후 추락 제한에서는 사용할 수 없다.

유효한 방향+점프키는 팔딱이 소유한다. 방향 없는 공용키 입력은 패링 창과 방향 입력 유예를 처리하며, 이미 패링으로 소비한 입력으로 팔딱을 추가 발동하지 않는다. 게이지에는 팔딱 필요량 표시선과 숫자를 띄운다. 충전 중에는 점프+팔딱 합계를 예약선으로, 발사 후에는 팔딱 비용만 표시한다. 노랑은 확보, 주황은 부족이며 사용 완료 시 숨긴다.

## 7. 오리 애니메이션·공격·탈락

### 오리 그림

사용자가 교체한 `오리1.png`(펼침), `오리2.png`(중간), `오리3.png`(닫힘)을 사용한다. 평상시3→2→1→2→3 순서로 입과 날개 동작을 잇는다. 닫힘 유지0.20초·열기0.35초·열림 유지0.20초·닫기0.35초, 총1.10초 주기다.

전체 그림 폭을 세계 폭의1.9배로 하고 원본 비율을 유지한다. 입 중심을 화면 중앙에 맞추고 상단400세계단위만 노출되도록 몸통을 아래로 배치한다. 펼친 입은 화면 양옆을 약6%씩 넘는다. 프레임마다 크기를 바꾸거나 입 폭을 억지로 늘리지 않는다.

### 불 공격

중앙에서 수직 기준−60°~+60°를20° 간격으로7발 발사한다. 기본색6발과 반대색 특수1발이며 특수 불 위에는 ‘+’ 표시를 둔다. 불을 크게 그려도 기존 피격·패링 범위는 따로 유지한다.

스턴이 없는 첫 공격은 플레이 시작 후4.80초에 예고,5.00초에 발사,5.15초부터 복귀,5.30초에 상승 재개다. 이후5초 주기로 반복한다. 오리 공격 시계는 수둔 스턴 동안 멈추므로 실제 다음 발사도 그만큼 늦어진다. 놓친 공격을 한꺼번에 발사하지 않는다. 공격 정지 중에도 플레이어와 이미 발사된 투사체는 움직인다.

### 입 충돌과 탈락

사망선은 `max(DuckY+15, CameraBottom)`이며 화면 전폭에 적용한다. 물고기 중심이 이 선 이하이면 즉시 탈락한다. 입을 닫을 때만 죽는 규칙이나 PNG 윤곽별 충돌은 추가하지 않는다.

탈락 시 충전·팔딱·플랫폼 소속을 정리하고 캐릭터 잔상·×·원형 충격파·하단 섬광과 ‘오리 입 충돌 · 탈락’을 표시한다. 전용 덜컥 소리와 함께0.09초 멈칫한 뒤0.24초 감쇠 흔들림을 준다. 화면 점수와 메뉴는 고정하며, 정지 시간을 쌓아 두었다가 빠르게 재생하지 않는다. 탈락한 사람의 표시를 유지한다. 전원 탈락 시 짧은 충돌 연출과1초 안내 후 게임 오버 메뉴로 넘어간다.

## 8. 불 피격과 패링 피드백

### 불 피격

불에 맞으면 게이지20을 잃고0.3초 스턴된다. 수영·충전·점프·팔딱·패링 입력을 막고 진행 중인 충전·팔딱 직진을 취소한다. 중력과 기존 이동 관성·오리 추격·다른 플레이어는 계속 진행한다. 스턴 중 겹친 불은 추가 피해나 스턴 연장을 주지 않으며, 회복 후에는 다시 맞을 수 있다.

불 색의 충격파·십자 섬광과0.5초 깜빡임, 별3개, ‘불 피격’ 및 기절 남은 시간을 표시하고 기존 hit 효과음을 재생한다. 사망과 재시작 시 남은 효과를 지운다.

### 패링 성공·실패

래피는 파란 특수 불, 블피는 빨간 특수 불을 유효한 판정 창에서 패링할 수 있다. 성공하면 불을 제거하고100점과 무료 도약을 제공한다. 성공 위치에 기존5프레임을0.13초씩 총0.65초 재생하고 황금 충격파·십자 섬광·‘패링 성공! +100점’을 표시한다. 효과는 도약하는 물고기를 따라 화면 위로 사라지지 않게 성공 위치에 남긴다.

0.36초 전용 성공음을 재생하고 같은 도약의 일반 jump/splash 호출은 겹치지 않게 한다. 성공 패링에는 피격 스턴을 적용하지 않는다. 잘못된 색의 특수 불 또는 일반 불 접촉은 성공 연출을 주지 않으며 피격 규칙을 따른다.

## 9. 아이템 배치와 수둔 명중

### 공통 배치

수둔과 건사료 모두 물 안 또는 물 위 공중에 생성한다. 매 판 공중 선택 확률을30~70% 사이에서 뽑은 뒤 개별 배치를 추첨하므로 실제 수량 비율은 매번 달라진다. 첫 두 보상은 유효한 위치가 있으면 서로 다른 배치 유형을 시도한다.

주 경로 아이템 생성 확률은0.65, 측면 경로는전체 기대량을 나눠 과도한 보상을 막는다. 생성 아이템 중 수둔 선택 확률은0.4다. 공중 아이템은 물 표면 위48~70에 두고 물과의 여유40, 아이템 간 간격70을 검사한다. 유효한 공중 위치가 없거나 뒤에 생성한 물이 덮으면 원래 물 안으로 옮긴다. 공중 아이템은 점프·팔딱 등의 비행 중 지나가야 먹을 수 있다.

두 아이템은80×80으로 표시한다. 건사료는 게이지24를 회복하고 수둔은 획득 즉시 아래로 발사한다. 아이템 난수와 물 배치 난수를 분리해 보상 조정이 지형까지 바꾸지 않도록 한다.

### 수둔 명중과 오리 스턴

수둔은72×140으로 표시하고420의 속도로 내려간다. 화면 안 X범위에서 입 경계 `DeathY+45` 이하에 도달하면 한 번만 명중 처리하고 투사체를 제거한다. 빠르게 경계를 통과해도 명중을 놓치지 않으며 화면 양옆 밖의 투사체는 점수를 주지 않는다.

공격량은 `max(10, 발사 시 게이지×WaterDamageScale)`이며 현재 계수는1이다. 공격량의5배가 점수이므로 최소50점을 보장한다. 발사 시 게이지60이면300점이다. 명중할 때만 실제 점수를 지급하고 팝업은 실제 증가량을 표시한다.

명중 시 물보라·충격파·오리 흔들림·점수 팝업과 splash 효과음을 주고 오리를1.2초 기절시킨다. 상승·카메라·공격 준비 시계는 멈추지만 플레이어와 기존 불은 계속 움직인다. 별·남은 초·막대로 상태를 표시한다. 여러 명중은 각각 점수를 주되 스턴은1.2초로 갱신하고 시간을 합산하지 않는다.

## 10. 점수·화면 흐름

`총점 = (두 캐릭터의 최고높이 합 ÷ 10)×10 + 누적 공격량×5 + 구간 최초 보너스`

구간 경계는 최고높이0/300/700/2200/4000/6000세계단위이며 보너스는0/100/200/300/400/500점이다. 최종 점수는 정수로 표시한다. 오리를 멈추는 수둔은 생존 시간을 벌면서 공격 점수도 주는 보상으로 사용한다.

화면 흐름은 타이틀→1.5초 준비→플레이→전원 탈락 연출→게임 오버다. 일시정지·기록 화면에서는 게임 진행을 멈추고 재시작 시 점수·타이머·피격/스턴/팔딱 상태를 초기화한다. 한 명만 탈락하면 생존자의 플레이를 유지한다.

## 11. 리소스·성능 관리

- 최종 리소스는 **PNG99·WAV19(배경4+효과15)·MP3 10, 총128개**다. PNG96개는 사용 중, 메뉴/게이지용3개는 미사용 보관이다.
- 새 오리3장을 사용하고 이전 오리입1/2/3은 현재 파일 목록에서 제외한다. 입 충돌 전용 `sfx_bite.wav`를 추가하고 `sfx_parry.wav`를 교체했다.
- 원본 PNG를 바꾸지 않고 로딩 시 긴 변을 배경/타이틀1536, 오리2048, 물640, 그 외256픽셀로 제한한다. 투명도와 종횡비를 유지한다.
- 최근 사용 순서의 이미지 캐시를96MiB·96개 한도로 관리한다. 이 수치는 캐시 픽셀 저장량 기준이며 디코더 임시 메모리와 드라이버 메모리까지 포함한 보장은 아니다.
- 입력 배열·접촉 목록·브러시를 재사용하고 충돌 후보를 한 번 순회하며 짧은 임시 배열 할당을 줄인다. 물리 갱신은1/120초로 유지한다.
- 절차적 WAV 생성은 기존 `tools/generate_audio.py`에서 관리한다. 패링/입 충돌음만 다시 만들 때 `--only sfx_parry sfx_bite`를 사용한다.
- 오디오 장치 대응은 교수님 제공 방식의 범위로 두며 이번 게임 기능 변경과 문서 갱신에서 수정하지 않는다.

## 12. 확인 결과와 남은 검증

오늘 최종 속도165를 적용한 **원본 Debug·Release 각각 빌드 성공 및112/112 자동 검사 통과** 기록을 확인했다. 이번 문서 갱신에서는 게임 코드를 바꾸거나 검사를 새로 실행하지 않고, 그 최종 결과와 현재 파일을 대조했다.

확인된 범위는 방향 입력·팔딱·패링·비용·물 접촉·고속 불 충돌·피격 스턴·수둔 스턴·점수 중복 방지·탈락 정리·공격 주기·상승 속도·재시작과100개 시드의 아이템 배치다. 그래픽 검증용 장면에서 수둔/탈락 및 두 캐릭터의 불 피격 효과가 표시되는 것을 확인한 기록이 있다. 장시간 실제2인 플레이와 청음 평가까지 완료했다는 뜻은 아니다.

최종 속도165의 별도 준비된120개 협력 이동 구간은 사전 충전과 점프·팔딱 사용으로 통과했다. 가장 느린 이동2.483초, 완료 시 최소 바닥 여유235.1세계단위다. 과거 속도90의 순차 충전 검사와 구분한다. 구간별 준비 검사이므로 연속 플레이의 게이지 부족이나 사람의 반응 시간을 보장하지 않는다.

다음 플레이 확인 항목:

1. 두 사람이 미리 충전하고 물 색을 바꾸는 협력이 실제 키보드 동시입력에서도 가능한가.
2. 0.3초 불 피격 스턴 뒤 조작 복귀가 명확하고 연속 피격 압박이 과하지 않은가.
3. 패링 성공음과 입 충돌음이 배경음 속에서 구별되는가.
4. 수둔의1.2초 스턴이 회복 기회를 주되 과도한 연속 정지를 만들지 않는가.
5. 긴 연속 플레이에서도 회복·점프·팔딱 소비와 오리 속도165가 적절한가.
