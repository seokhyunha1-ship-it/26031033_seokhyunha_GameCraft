1. 기존 기획의 유지 사항과 미확정 사항
==================================================
1-1. 게임 정체성 및 유지 기준
- 래피와 블피가 물 플랫폼을 타고 오리에게서 도망치는 종스크롤 2D 게임.
- 헤엄, 충전 점프, 색 전환, 협력, 패링, 최고 기록 경쟁이 중심이다.
- 오리 처치 클리어는 없으며 두 물고기가 모두 탈락하면 게임 오버.
- 한 물고기가 죽어도 나머지는 계속 플레이한다.
- 게이지는 각자 관리한다. 현재 초기값과 상한은 100, 하한은 0.
- 래피는 파랑 물을 빨강으로, 블피는 빨강 물을 파랑으로 바꾼다.
- 현재 공중의 자기 색 물 접촉은 입수를 거부하고 추락 전용 상태로 만든다.
  반대 색 물에 접촉해 색을 바꾸며 입수하면 추락 제한이 해제된다.
  시작 물과 상승 중 출발 물의 예외는 기존 판정을 유지한다.
- 같은 순간의 접촉은 변경 전 색을 공유하며, 순차 접촉은 실제 시간순으로 처리한다.

1-2. 최근 대화에서 확정한 조작과 물리
- 래피 WASD / 블피 방향키로 상하좌우 헤엄.
- 점프 충전은 래피 Space / 블피 ]. 떼면 일반 점프.
- 충전 중 W+A/D 또는 위+좌/우를 누른 시간에 비례해 점프를 편향한다.
  현재 조정값은 1초에 최대 좌우 30도이다.
- 충전 중에도 평소의 중력, 부력, 헤엄, 지연, 게이지 규칙을 적용한다.
- 물에서 이탈하면 충전을 취소하며 공중에서 충전 점프를 새로 만들지 않는다.
- 점프 상승과 하강 내내 좌우 공중 조절 가능. 기존 2초 제한은 폐기된 사항이다.
- 비행 거리별 게이지 소모를 유지한다. 현재 100px당 1포인트.
- 물 플랫폼은 가로뿐 아니라 세로로도 크기를 다양화한다.
- 세로·대각선 헤엄은 기본 자세 이미지를 사용한다.
- 입수한 물의 숨은 이탈 여유는 작게 둔다. 현재 좌우8/위6/아래12px.

1-3. 현재 유지할 수치와 기능
- 세계 단위 1m=10px. 여기서 px는 이후에도 '세계 단위'이며 화면 픽셀과 구별한다.
- 일반 점프: 충전50포인트/초, 최소1포인트, 최대100포인트, 현재 보유량 이내.
- 일반 점프 기준 높이: 소비1포인트당0.5m. 중력260px/s².
- 패링: 특수 불만 가능. 래피는 파랑, 블피는 빨강.
  판정0.20초/거리30px, 성공 데미지20, 현재 게이지×0.4 상당의 무료 도약.
- 불: 4초 간격, 기본색6발+반대색 특수1발, 총7발.
  수직 기준 -60~+60도/20도 간격, 속도180px/s, 피격 게이지20 감소.
- 수둔은 획득 즉시 아래로 발사하며 실제 오리 충돌 때 공격 점수를 얻는다.
  현재 데미지 계수1, 건사료 회복30, 게이지 상한100.
- 점수=(두 캐릭터 최고높이m의 합)×10+누적 실제데미지×5+구간 최초 보너스.
- Pause/Results에서는 게임 시간이 흐르지 않으며 재시작 시 게임 상태를 초기화한다.
- 최신 문서의 시작 흐름은 타이틀→1.5초 준비→물에서 시작이다.
  초기 초안의 땅 출발/최초 오리 등장 연출을 이번 수정에서 복원하지 않는다.

1-4. 아직 확정하지 않은 이번 설계의 선택 사항
- '약20개'의 기준 플랫폼 폭, 빈틈 포함 여부, 실제 한 줄 생성 수.
- 팔딱의 공중 사용 횟수, 4방향/8방향, 속도 교체/힘 가산 방식.
- 0.3초의 정확한 의미, 방향키를 미리 누르고 있던 경우의 허용 여부.
- 패링 도약 직후 팔딱 허용 여부와 같은 버튼의 패링 우선순위.
- 오리 입 개폐가 시각 연출인지, 닫힐 때만 사망하는 판정인지.
아래에 일관된 구현 제안을 제공하되 확정 규칙으로 승격하지 않는다.

2. 현재 문제점과 개선 방향
==================================================
P01. 창 해상도만 키워서는 선택 가능한 경로가 늘지 않는다.
현재 게임은 960×720 기준이며 생성 경계, 시작 물, 불 발사 위치,
오리 그림, 메뉴 등에 960/480/940 같은 고정값이 사용된다.
개선: 창 크기, 보이는 세계 범위, 플랫폼 생성 범위를 분리하여 함께 수정한다.

P02. 넓은 화면은 물고기와 불도 작게 만든다.
개선: 배율과 UI를 분리하고 실제 화면에서 가독성을 확인한다.
플랫폼 크기만 줄여 기존에 확정한 큰 헤엄 공간을 없애지 않는다.

P03. 팔딱 비용의 기준이 모호하면 사용자가 비용을 예측할 수 없다.
개선: 최초 일반 점프에서 실제로 지불한 비용을 기록한다.
충전 중 표시량이나 팔딱 직전 잔여 게이지의 절반으로 계산하지 않는다.

P04. 래피 Space는 현재 점프와 패링이 겹친다.
개선: 팔딱을 추가할 때 같은 입력으로 팔딱·패링을 동시에 실행하지 않도록 중재한다.
키 변경은 이번 확정 요청이 아니므로 임의로 변경하지 않는다.

P05. 오리 상승 정지는 평균 추격 속도도 바꾼다.
개선: 상승속도와 정지시간을 분리해 기록한다. 단순히 속도만 올려 보상하지 않는다.

P06. 가로 확장 시 중앙에서 쏘는 불이 가장자리까지 닿기 어렵다.
개선: 이번에는 기존7발/4초를 유지하고 위치별 피격·패링 기회 차이를 측정한다.
다중 발사구나 조준 공격은 별도 제안으로 남긴다.

P07. 문서와 검증 결과의 버전이 일치하지 않는다.
빌드 보고서는30/30, 첨부 테스트 파일은46/46이다.
최근 변경 기록에는 중간51/52 및 최종 재검증 차단 기록이 있다.
따라서 최신 게임 전체 검증 통과라고 단정할 수 없다.
초안의 무작위 방향 선택, W/위 점프, 충전 중 제자리 유지도 최신 기준이 아니다.

3. 넓은 맵 화면 명세
==================================================
[확정]
가로 화면 안에 플랫폼이 약20개 들어갈 수 있는 넓은 맵을 제공한다.
여러 경로 중 선택할 수 있도록 한다.

[구현 제안: 해상도와 약20개의 정의]
- 기본 출력 창: 1920×1080. 작은 창에서는 종횡비 유지 및 여백 처리.
- 대표 플랫폼 폭 Wref=180 세계px, 대표 간격 Gap=24 세계px.
- 좌우 여백 Margin=40 세계px, 대표 수 N=20.
- 보이는 세계 폭=2×Margin+N×Wref+(N-1)×Gap=4136 세계px.
- 보이는 세계 높이=4136×9/16=2326.5 세계px.
- 배율=1920/4136≈0.4642. 대표 플랫폼은 약83.6 화면px.
- 이 기준은 '폭180의 대표 플랫폼을 간격 포함20개 놓을 수 있는 폭'이다.
  소·중·대 플랫폼이 섞인 모든 줄에 정확히20개를 강제한다는 뜻은 아니다.
- 기준 폭180과 출력1920×1080은 제안값이다. 사용자가 의도한 약20개의
  의미가 실제 생성 개수라면 별도 밀도 조건으로 변경해야 한다.

[세계와 화면]
- 월드 좌표와 물리 단위는 유지한다. 확대/축소로 점프 높이나 점수가 바뀌면 안 된다.
- 화면x=(세계x-카메라왼쪽)×배율+화면여백x.
- 화면y=(카메라상단세계y-세계y)×배율+화면여백y. 세계 위쪽은+Y.
- UI는 화면 좌표로 그려 세계 축소의 영향을 받지 않게 한다.
- 마우스 입력은 화면여백과 배율의 역변환으로 판정한다.
- 동일 종횡비의 창 크기 변경은 보이는 세계 범위를 바꾸지 않는다.
- 기존 상향 전용 카메라 정책과 생존 물고기 추적을 유지한다.
  추적 기준의 화면 비율은 기존 화면의 위치 비율로 옮기고 고정px를 제거한다.

[플랫폼 생성]
- 기존 소형130~210/중형250~360/대형430~570 세계px 폭을 유지한다.
- 주 경로 높이80~260, 추가 경로80~220 및 기존 이탈 여유를 유지한다.
- 생성 좌우 경계를 WorldWidth에 연결하고 시작 물도 전폭으로 확장한다.
- 중앙 주 경로의 도달성 조건을 유지하면서 좌우에 분기와 재합류를 만든다.
- 주 경로 간 수평 겹침60px 이상, 물 영역 사이 최소12px,
  기존 주 경로 표면 간격150px 이내 조건을 확대 화면에서도 검사한다.
- 넓은 구간은 기존 측면2개 제한 대신 공간을 반복 분할하여 채운다.
  추가 물 사이 수평 간격24px 이상, 월드 경계 준수, 물 영역 중첩 금지.
- 최소한 중앙과 좌우의 연결된 경로를 제공한다. 장식처럼 고립된 물만 늘리지 않는다.
- 색과 게이지에 따라 실제 이용 가능 여부가 달라지므로 기하학적 연결과
  실제 두 캐릭터 이동 가능성을 별도로 검증한다.
- 팔딱 없이 통과 가능한 주 경로를 유지하는 것을 기본 제안으로 한다.
- 생성 범위는 카메라상단+1000세계px까지 확보한다.
  정리는 화면하단보다650세계px 아래를 기준으로 하되 생존자·현재 입수 물은 보존한다.
- 추가 물 수가 늘면 아이템 수도 급증하므로 측면 경로 전체의 생성 기대량을
  기존 측면 경로 기대량 수준으로 분배하는 것을 제안한다. 새 확정 규칙은 아니다.

[가독성 및 실패 기준]
- 실제 1080p에서 물고기 위치, 물 색, 특수 불 표시, 게이지를 구분할 수 있어야 한다.
- 축소 때문에 구분이 어렵다면 먼저 외곽 표시/UI 보완을 제안한다.
  세계 폭이나 캐릭터 충돌 크기를 자동으로 바꾸지 않는다.
- 확대 범위로 발생한 경로 단절, 화면 밖 물고기 미표시, 하단 잘림은 수정 대상이다.

4. 신규 공중 이동 '팔딱' 명세
==================================================
4-1. 확정된 요구
- 명칭: 팔딱.
- 점프 중 점프 버튼을 한 번 더 누르면 방향 입력을 받아 발동한다.
- 지정 방향으로 공기를 튕겨 추가 비행한다.
- 비용은 해당 점프에서 사용한 점프 게이지의 절반이다.
- 방향키 입력 제한시간을 넘기면 발동하지 않는다. 0.3초는 예시로 제시된 값이다.

4-2. 비용과 사용 자격 [구현 제안]
- 일반 점프 성공 시 LastPaidJumpCost=실제 차감량 J를 저장한다.
- 팔딱 비용 C=J×0.5. 소수 포인트를 유지한다.
- 성공 순간 현재 게이지 G>=C일 때만 C를 한 번 차감한다.
- 비용 부족이면 약한 팔딱이나 음수 게이지를 만들지 않고 실패한다.
- 공중 이동 거리 소모는 별도로 계속 적용한다. 팔딱 비용에 합쳐 반으로 줄이지 않는다.
- 일반 점프 한 번의 비행 구간당 팔딱 성공은1회로 제한한다.
- 정당한 입수 후 다음 일반 점프가 성공할 때 횟수와 기준 비용을 갱신한다.
- 단순 물 이탈, 충전 취소 후 낙하, 자기 색 물 거부의 추락 전용 상태에서는 불가.
- 사망/입수/재시작 시 대기 입력과 사용 자격을 초기화한다.
- 패링 무료 도약은 새 유료 점프가 아니다. 패링 성공 시 팔딱 자격을 종료하는
  보수적 방식을 제안한다. 무료 무한 팔딱이나 비용0 팔딱을 만들지 않는다.
- 실패 입력은 게이지와 성공 횟수를 소비하지 않는다. 재시도는 버튼을 떼고 다시 눌러야 한다.

비용 예시
1) 점프 직전100, 일반 점프40 사용 →60. 이동 소모3 후57.
   팔딱 비용20 →성공 후37. 이후 거리 소모는 계속된다.
2) 일반 점프80 사용 →잔여20. 팔딱 비용40이므로 추가 회복이 없다면 사용 불가.
3) 일반 점프1 사용 →팔딱 비용0.5. 일반 점프의 최소비용1을 팔딱에 재적용하지 않는다.
주의: 팔딱을 예약하지 않고 일반 점프에 전량 사용하면 팔딱을 쓸 수 없다.
100 보유에서 이동 소모를 제외해도 J+J/2<=100, 즉 J<=약66.67이어야 한다.
충전 UI에 '점프 비용 / 팔딱 필요량'을 함께 표시하는 것을 제안한다.

4-3. 방향 입력 시간 [구현 제안]
- DirectionWindowSeconds=0.30초.
- 기준 t0는 공중에서 점프키를 새로 누른 시각이다. 일반 점프 발사 시각이 아니다.
- t0에 방향키를 이미 누르고 있으면 해당 방향으로 즉시 시도한다.
- 방향이 없으면 t0~t0+0.30초 동안 처음 유효한 방향을 기다린다.
- 입력 지연<=0.30초면 허용, >0.30초면 이번 시도는 취소한다.
- 방향키를 오래 누른 시간 자체를 실패 조건으로 보지 않는다.
  이는 예시 문구의 '제한시간'을 입력 유예시간으로 해석한 제안이다.
- 대기 중에도 중력·비행·피격·거리 소모가 진행된다. 성공 순간 비용을 재검사한다.
- 점프키 자동 반복은 새 시도로 취급하지 않는다. 키를 계속 누르면 연속 발동하지 않는다.
- 방향 유예 중 점프키를 떼어도 유예는 유지한다. 입수/사망/패링 성공은 즉시 취소한다.
- Pause에서는 유예 시간이 멈춘다. 복귀 시 과거 키 눌림을 새 입력으로 재생하지 않는다.

4-4. 방향과 힘 [구현 제안]
- 상하좌우 및 대각선8방향을 허용한다.
- 좌+우, 위+아래는 각 축에서 상쇄한다. 두 축이0이면 유효 방향이 아니다.
- 대각선은 정규화하여 직선보다 강해지지 않게 한다.
- 팔딱 속도 V=sqrt(2×Gravity×(C×JumpMetersPerPoint×PixelsPerMeter)).
- 순간 속도를 Velocity=Direction×V로 교체하는 방식을 초기 제안으로 한다.
  기존 속도에 계속 가산하는 방식과 비교할 수 있도록 분리해 구현한다.
- 위 식은 수직 방향의 기준 높이 환산이다. 모든 방향에서 같은 비행 거리를 보장하지 않는다.
- 이후 중력과 기존 좌우 공중 조절을 즉시 적용한다. 순간이동이나 무적은 없다.
- 기존 일반 점프 Launch는 위쪽30도 제한을 적용하므로 그대로 호출하지 않는다.
  TryFlap을 분리하여 아래/수평 방향이 위쪽으로 강제되는 오류를 방지한다.
- 팔딱 뒤에도 기존 물 색 접촉 규칙을 적용한다. 자기 색 물 거부를 우회하지 않는다.
- 출발 플랫폼 기억은 유지하되 기존 상승 이탈 예외만 적용한다.

4-5. 패링과의 입력 충돌 [구현 제안: 구현 전 검토 우선 항목]
- 현재 점프키 입력도 패링 창을 열며 래피는 Space가 별도 패링키와 동일하다.
- 기존0.20초 패링 기회를 보존하기 위해 패링과 팔딱을 한 입력의 중재기로 묶는다.
- 동일 입력으로 패링 창을 열고 팔딱 후보 방향을 저장한다.
- 첫0.20초에 패링 성공 시 무료 도약만 수행하고 팔딱 후보는 취소한다.
- 패링 실패/피격으로 해당 입력이 처리되면 팔딱도 취소하여 한 입력의 중복 결과를 막는다.
- 0.20초가 끝나고 패링으로 처리되지 않았다면 저장된 방향으로 팔딱을 시도한다.
- 방향이 아직 없으면 남은0.10초 동안 기다린다. 시간 초과 시 취소한다.
- 블피의 Enter만 누른 경우에는 패링만 수행한다. 팔딱 후보를 만들지 않는다.
- 단점: 방향을 함께 눌러도 팔딱 반응이 최대0.20초 늦어진다.
  사용자 요청의 즉각적인 조작감과 충돌할 수 있으므로 '확정'이 아닌 추천 비교안이다.
- 대안은 별도 패링키 배정 또는 방향 동시 입력 시 팔딱 우선이다.
  두 대안 모두 기존 조작/패링 기회가 달라지므로 자동 적용하지 않는다.

5. 오리 추격·입 개폐·불 공격 명세

[확정]
- 오리 입이 열리고 닫히는 동작을 반복하며 아래에서 위로 추격한다.
- 몸통 리소스가 없어도 기존 오리입1~3 이미지를 사용한다.
- 불을 뿜을 때는 잠시 상승을 멈춘다.
- 상승 속도, 개폐 속도, 발사 지연, 정지시간은 초기값을 정하고 조정한다.

[초기 조정값 및 상태 제안]
DuckRiseSpeed=13 세계px/초 (기존값 유지).
MouthOpenSeconds=0.35초, MouthOpenHoldSeconds=0.20초.
MouthCloseSeconds=0.35초, MouthClosedHoldSeconds=0.20초.
입 개폐1주기=1.10초.
FireIntervalSeconds=4.00초 (기존 실제 발사 간격 유지).
FireWindupSeconds=0.50초 (발사 예고).
FireHoldSeconds=0.30초 (발사 후 입을 열고 정지).
FireRecoverySeconds=0.40초 (복귀 동작 중 정지).
정지 합계=1.20초. 공격 준비부터 복귀까지 상승을 멈추는 해석을 제안한다.

Playing 시작 기준 시간표
0.00~3.50초: 추격+입 개폐 반복.
3.50~4.00초: 발사 예고. 상승 정지, 입을 여는 동작.
4.00초: 기존7발을 한 번 발사.
4.00~4.30초: 입 열린 상태로 정지. 추가 발사는 하지 않는다.
4.30~4.70초: 닫는 복귀 동작 중 정지.
4.70~7.50초: 추격+입 개폐 반복.
7.50초부터 다음 예고, 8.00초 두 번째 발사. 이후 동일 반복.

- AttackCooldown을 '복귀 후4초'로 다시 세지 않는다. 그러면 기존 발사 간격이 바뀐다.
- 첫 발사는 Playing의4초이다. 타이틀/준비/Pause/Results 시간은 제외한다.
- 정지 중 DuckY만 멈춘다. 물고기·불·수둔·카메라는 각자의 규칙으로 계속 움직인다.
- 정지한 오리에도 수둔이 충돌하며 기존 데미지 점수를 준다.
- 수둔/패링 공격이 추격 정지시간을 추가 연장하지 않는다.
- 오리 위치는 세계 좌표로 관리한다. 카메라가 움직여도 화면 하단에 강제 재배치하지 않는다.
- 화면 밖으로 내려간 경우 위치 표시를 제안하되 즉사선을 화면에 끌어올리지 않는다.
- 한 주기의 평균 상승속도=13×(4-1.2)/4=9.1세계px/초.
  기존13보다 평균 압박이 줄어드는 점을 플레이 테스트에서 확인한다.

[입 그림과 충돌]
- 파일번호만으로 열림 순서를 추정하지 말고 실제 그림을 확인해
  ClosedFrame / HalfOpenFrame / OpenFrame을 지정한다.
- 평상시 닫힘→중간→열림→중간→닫힘 순서. 발사 때 열림 상태를 사용한다.
- 기존 사망 경계는 물고기 중심Y<=DuckY+15이다.
  이번 기본안에서는 개폐와 별개로 이 위험 경계를 유지한다.
- '닫힐 때만 먹힘'은 새로운 게임 규칙이므로 자동 추가하지 않는다.
- 넓어진 맵에서도 위험 경계는 전폭. 오리 입 그림도 전폭에 맞추되
  가로 확장에 따른 그림 왜곡을 실제 화면에서 확인한다.
- 불 발사점은 WorldWidth/2와 DuckY로 설정하고 기존 중앙 발사를 유지한다.

기존 GameWorld 고정 갱신1/120초와 렌더링 분리를 유지한다.

GameSettings.cs 및 game-settings.json

GameModel.cs / FishPlayer
- LastPaidJumpCost, FlapUsed, FlapPending, FlapDeadline,
  FlapDirection, PendingInputId, FlightOrigin을 추가한다.

- 성공시 비용 차감, 속도 변경, 횟수 소비, 후보 해제를 한 번만 수행한다.
- 이동 거리 소모는 실제 이동 구간만 계산한다. 물 접촉 보정·벽 보정은 제외한다.
- 오리 상태와 상태 경과시간을 추가하고 상승·개폐·발사 이벤트를 분리한다.
- 플랫폼 생성, 월드 경계, 시작 위치, 불 발사 위치의 고정960/480/940을 제거한다.

GameMain.cs
- 입력의 눌림 시각과 새 눌림을 기록한다. 렌더 한 프레임에 물리 갱신이
  여러 번 돌아도 같은 입력을 반복 소비하지 않는다.
- 월드→화면 변환과 UI 좌표를 분리한다. 창 여백을 마우스 판정에서도 제외한다.
- 팔딱 비용/가능 여부/실패 이유를 짧게 표시한다.
- 이미지 변경 없이 우선 기존 점프 자세와 효과음을 활용한다.

BackgroundManager / ResourceManager
- 새 화면 범위에서 배경 빈틈 및 반복 경계를 검사한다.
- 배경 구간은 기존 세계 높이를 사용한다. 화면 확대 때문에 구간 진입 점수가 달라지면 안 된다.
- 원본 이미지와 알파를 유지하고 개폐 프레임의 의미만 매핑한다.

동일 갱신의 처리 원칙
- 입력 후보 등록→오리 상태 진행→물고기 이동/접촉/불 판정→패링 중재 완료→팔딱 확정.
- 같은 시각의 사망/입수가 팔딱보다 우선한다. 이미 죽은 물고기를 되살리지 않는다.
- 패링 성공 틱에 팔딱이나 일반 점프 비용을 추가 차감하지 않는다.
- 시각 비교는 고정 틱과 입력 시각을 함께 사용하고0.30초 경계 포함 여부를 테스트한다.
- Pause는 모든 상태 타이머를 멈추고 Restart는 모든 후보·상태·난수를 초기화한다.

- 두 사람이 같은 키보드로 점프·방향·패링 동시입력을 시험한다.
- 학교 PC의 오디오 장치 없는 환경에서 실행 가능한지도 별도로 확인한다.
  관련 대화의 오류는 확인했으나 이번 문서 작업에서 수정·실행 검증하지 않았다.
- 새 빌드와 검증 로그에는 버전/날짜/실행 환경을 남긴다. 과거 통과 로그를 재사용하지 않는다.

8. 플레이 관찰과 변경 반영 절차
==================================================
1차: 넓은 화면 가독성 및 실제 선택 경로 확인.
2차: 팔딱 비용 예측, 방향 입력 실패율, 패링 충돌과 반응 지연 확인.
3차: 오리 추격 압박과 발사 정지시간 확인.
4차: 두 사람 협력과 색 변화 상황에서 통합 검증.

매 회차 동일한 시드·시작 게이지로 비교하고 한 번에 주요 변수 하나만 바꾼다.
기록 항목: 버전, 시드, 생존시간, 최고높이, 사망원인, 선택 경로,
팔딱 시도/성공/실패 사유, 사용 전후 게이지, 패링 성공률, 오리와의 거리.
0.3초가 짧은 문제와 키보드 동시입력 누락, 패링 중재 지연을 구분한다.
게이지 부족 실패가 많아도 비용 절반 규칙을 임의로 변경하지 않는다.
우선 충전량 안내와 경로·회복 여건을 검토한다.

9. 별도 아이디어 — 기본 구현에 자동 포함하지 않음
==================================================
A. 팔딱 비용을 충전 게이지에 별도 색으로 미리 표시한다.
B. 멀리 떨어진 동료와 화면 밖 오리의 방향·거리를 가장자리에서 알려준다.
C. 넓은 맵에서 중앙/외곽 위협 차이가 크면 오리 발사구 이동이나 조준 공격을 비교한다.
D. 팔딱을 즉시 발동시키기 위해 패링키를 분리한다. 사용자 키 선택 후 적용한다.
E. 입을 닫는 순간에만 포획하는 규칙은 추격 난이도를 크게 바꾸므로 별도 실험으로 둔다.

==================================================
10. 이번 산출물의 상태
==================================================
기존 자료와 최근 대화, 현재 소스의 주요 규칙을 대조한 수정 명세 초안이다.
게임 소스와 원본 기획서를 변경하지 않았고 새 빌드/자동 테스트/실제 플레이도 하지 않았다.
오리 시간 수치는 요청에 따라 초기값을 지정했다.
약20개 산정 기준, 팔딱 횟수/방향/물리 방식, 패링 중재는 구현 제안으로 남겼다.
특히 패링 중재 방식은 팔딱 반응성에 직접 영향을 주므로 다음 구현 결정에서 우선 검토한다.
