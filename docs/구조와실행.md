# 구조와 실행

## 파일 책임

| 파일 / 객체 | 책임 |
|---|---|
| AppMain | 기존 STA 진입점, --self-test 분기 |
| GameMain | G2AppBase 연결, 상태·키·고정시간 갱신·UI·그리기 |
| GameSettings | JSON 초기값 |
| GameModel / GameWorld | 렌더러 없는 게임 시뮬레이션, 생성·추격·충돌·아이템 |
| FishPlayer / WaterPlatform / FireProjectile / WaterAttack / GameItem | 상태와 위치 |
| ScoreSystem | 최고 높이·데미지·일회 보너스 계산 |
| BackgroundManager | 높이별 이미지 선택·혼합 |
| ResourceManager | 이미지 경로·비율·캐시(최대28텍스처)·해제 |
| AudioManager | 별도 효과음/BGM 음량, 루프, 전환, 일시정지 |
| GameSelfTests | 독립적인 규칙 회귀 검사 |
| glc2d | 기존 Direct2D/XAudio2 기반 유지, DPI96·종횡비 및 음량/일시정지 보강 |

Playing에서만 GameWorld.Step을1/120초 단위로 호출한다. Pause/Results에서는 호출하지 않는다. 렌더 주기와 분리하고 입력 edge는 첫 물리 틱에만 소비한다. 모든 객체는 인스턴스 상태라 재시작 시 새 GameWorld로 초기화한다.

상태 흐름: Title→Ready→Playing→GameOver. Playing↔Paused. 메뉴에서 Results로 들어갔다가 원래 메뉴로 돌아간다. Restart는 새 Ready, Title은 타이틀로 이동한다.

## 실행

기존 솔루션: `src/csharpproject/26031033_seokhyunha_fishjump/26031033_seokhyunha_fishjump.sln`.
프로젝트 TargetFramework는 net9.0-windows, WinForms. 기존 NuGet 버전을 유지했다. Visual Studio2022의 .NET9 지원 버전 또는 설치된 .NET SDK로 빌드한다. 이 환경에서는 SDK10.0.401이 .NET9 대상으로 실제 빌드했다. VS GUI 자체의 빌드 버튼 검증과는 구분한다.

실행 파일은 프로젝트 `bin/ReleaseVerified/26031033_seokhyunha_fishjump.exe`. `assets` 폴더와 DLL·설정파일을 같이 유지한다. 다른 PC에는 .NET9 Desktop Runtime이 필요하다(자체 포함 배포가 아님).

```powershell
dotnet build src/csharpproject/26031033_seokhyunha_fishjump/26031033_seokhyunha_fishjump.sln -c Release
```

실행 파일에 `--self-test`를 붙이면 창 없이 검사하고 결과를 같은 폴더의 self-test-results.txt에 남긴다. `--asset-check`는 Direct2D로 모든 PNG를 실제 생성·해제하고 asset-check-results.txt에 기록한다. 오디오도 정상 초기화한 뒤 종료한다.

`game-settings.json`은 실행 파일 옆 파일을 읽는다. 소스 쪽 설정을 바꿨으면 다시 빌드한다. Seed 정수로 맵 재현. keys는 Windows Forms Keys 이름을 사용한다. 잘못된 JSON이나 키 이름은 수정 후 실행한다.

원본 오디오의 사용 권리 확인 후 UseProvidedEffects=true로 선택 가능하다. 기본값은 false다. BGM/기본 효과음 재생성은 `python tools/generate_audio.py`.
