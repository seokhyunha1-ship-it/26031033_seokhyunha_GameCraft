## 2026-11-08 추가 업데이트 — 추격180·불 가속·피격 스턴 (최신)

### 1. 속도

오리 기본 상승90→180세계단위/초. 기존 구간당+3을 적용해 마지막 구간195다. 불 속도는210→360세계단위/초로 높였다. 증가한 카메라 상승을 감안해 중앙 불도 화면에서 더 빠르게 올라오도록 정했다. 공격 주기5초, 공격 중0.50초 정지, 수둔 명중 스턴1.2초와 기존 점프/팔딱 수치는 유지한다.

### 2. 불 피격과0.3초 스턴

래피·블피 모두 불 피격 시 게이지20을 잃고0.3초 스턴된다. 충전·패링·대기 팔딱·팔딱 직진을 취소한다. 스턴 중 수영/충전/점프/팔딱/패링 입력은 무시하지만 키를 놓았는지는 추적하여 복귀 후 의도하지 않은 기술이 발동하지 않게 했다. 회복 후 새로운 입력으로 정상 조작할 수 있다.

물리 전체를 얼리지 않는다. 중력·기존 이동 관성·물 접촉·추격·다른 플레이어는 계속 진행한다. 스턴 중 겹친 불은 추가 피해나 스턴 갱신을 주지 않으며,0.3초가 끝나면 다시 피격될 수 있다. 고정120Hz 틱 경계에서 입력을 복원한다. 성공 패링에는 스턴을 적용하지 않고 잘못된 색 패링은 피격으로 처리한다. 탈락/새 게임에서 피격 효과와 스턴을 정리한다.

### 3. 피격 효과

피격 위치에 불 색의 원형 충격파·파편·십자 섬광을 표시하고 캐릭터를0.5초간 깜빡인다. 캐릭터 위에 기절 별3개와 남은 시간/불 피격 문구를 표시한다. 기존 hit 효과음을 한 번 재생한다. 기존 입 충돌의 멈칫과 흔들림, 패링 성공 효과 및 수둔 명중 연출은 유지한다. 새 이미지·음원 없이 기존 리소스와 도형을 사용한다.

### 4. 검증

- 검증 복사본 Release: **112/112 통과**. 양쪽 캐릭터의 스턴·입력 차단/복원, 충전/팔딱 취소, 중복 피해 억제, 중력 유지, 성공 패링 예외, 빠른 불의 선분 충돌, 탈락/새 게임 정리, 설정값 검사를 포함한다.
- 기존 순차 충전 협력 검사는 속도90을 명시한 과거 기준 검사로 보존했다. 속도180에서는 같은 방식이 실패했다(첫 사람 도착 이후 두 번째 충전은 늦음). 이를 통과한 것처럼 보고하지 않는다.
- 속도180용으로 두 사람이 미리 충전하고, 먼저 반대 색 캐릭터가 점프·팔딱으로 물 색을 바꾼 뒤 동료가 따라오는 실제 입력 시뮬레이션을 추가했다.30개 시드의120구간 통과, 가장 느린 이동2.483초, 완료 시 최소 바닥 여유208.5세계단위. 각각 따로 준비한 구간으로 장시간 연속 플레이나 사람의 반응 시간을 보장하지 않는다. 자동 충전/자동 팔딱 기능을 게임에 넣은 것은 아니다.

## 2026-11-08 추가 업데이트 — 패링·입 충돌 타격감·상승90 (최신)

### 1. 패링 성공

성공 위치를 따로 저장하고 기존5프레임을240×240세계단위로0.65초 재생한다(기존120×120, 0.4초). 원형 충격파·십자 섬광·‘패링 성공! +100점’을 추가했다. 효과가 도약하는 캐릭터를 따라 빠르게 위로 사라지지 않는다. 성공 판정과 동시에 전용 parry 소리만 호출하고, 해당 도약의 일반 jump/splash 호출을 제거했다. 일반 점프 소리는 유지한다. 잘못된 색 또는 일반 불 접촉은 성공 연출을 발생시키지 않는다.

### 2. 입 충돌

사망 판정은 즉시 적용한다. 입 충돌 전용 bite 소리와 함께0.09초 멈칫,0.24초 감쇠 흔들림(최대 가로6·세로4화면픽셀)을 추가했다. 점수와 메뉴는 흔들지 않는다. 입력은 멈칫하는 동안에도 수집하고 물리 시간만 정지하며, 지나간 시간을 누적해 급가속시키지 않는다. 같은 순간 두 명이 탈락해도 멈춤 시간을 합산하지 않는다. 기존 탈락 문구/섬광과 게임 오버 전1초 안내는 유지한다.

### 3. 속도

기본 상승75→90. 구간당+3을 유지하므로 마지막 구간105다. 공격 주기5초와0.50초 정지, 수둔 스턴1.2초는 유지한다.

### 4. 효과음과 리소스

기존 sfx_parry.wav를0.36초 금속성 성공음으로 교체하고 sfx_bite.wav를0.22초 저음 충격/딱 소리로 추가했다. 기존 tools/generate_audio.py에서 표준 라이브러리로 합성하며 외부 음원을 사용하지 않는다. --only 옵션을 추가해 다른 리소스를 다시 쓰지 않고 두 소리만 생성했다. PCM은22,050Hz·16bit·모노이며 피크/무음/클리핑/끝부분을 수치 검사했다. 오디오 장치 대응 코드는 변경하지 않았다.

### 5. 검증과 제한

- 검증 복사본 Debug/Release 빌드는 성공했다. 그러나 Windows 애플리케이션 제어가 새 DLL 로딩을0x800711C7로 차단해 해당 실행의 자동 검사와 실제 화면·청음 검증을 완료하지 못했다. 이전104개 결과를 새 코드 통과 결과로 사용하지 않았다.
- 양쪽 플레이어의 패링 성공/실패와 소리 중복 방지, 성공 위치 고정·5프레임·효과 종료,30/60/144fps에서 멈칫0.09초와 흔들림 종료를 검사하는 항목3개를 추가했다(총107개). 기본 속도 검사도90으로 수정했다.
- 원본 Debug·Release 빌드 성공, 실제 EXE 각각107/107 자동 검사 통과, 종료 코드0. 두 새 효과음의 빌드 출력도 원본과 해시 일치를 확인했다.
- Windows 보안 설정은 변경하지 않았다. 실행 정책이 계속 차단할 경우 실제 실행 검증은 미완료 상태로 남는다.

### 6. 변경 파일

## 2026-11-08 추가 업데이트 — 탈락 표시·아이템 확대·수둔 스턴 (최신 적용)

### 1. 탈락과 충돌 표시

기존 화면 하단 사망 경계는 유지한다. 경계에 닿는 순간 Alive를 해제하고 충전·팔딱·소속 플랫폼을 정리하며 기존 hit 효과음을 한 번 재생한다. 충돌 위치에1.4초 동안 캐릭터 잔상, ×, 퍼지는 원과 파편, 하단 섬광 및 ‘P1/P2 오리 입 충돌 · 탈락’을 표시한다. 이미 죽은 캐릭터에는 다시 효과나 소리를 발생시키지 않는다. 한 명이 살아 있으면 계속 진행하며 우측 상단의 탈락 표시는 남는다.

두 명 모두 탈락하면 물리를 멈추고1초간 시각 효과를 보여준 뒤 게임 오버 메뉴로 전환한다. 게임 오버에도 ‘오리 입 충돌 · 두 플레이어 탈락’ 사유를 표시한다. 판정은 실제 PNG의 투명 픽셀이나 개폐 윤곽이 아니라 기존 하단 경계 기준이다.

### 2. 아이템과 수둔 표시 크기

수둔·건사료는36×36→80×80세계단위(가로·세로 약2.2배), 발사된 수둔은36×70→72×140(2배)로 확대했다. 획득 반경35와 공중 아이템의 점프/팔딱 획득 조건은 유지한다. ItemDrawSize 설정으로 아이템 표시 크기를 조정한다.

### 3. 수둔 명중과 점수

하향 수둔이 화면 안 X범위에서 입 경계 DeathY+45 이하에 도달하면 한 번만 명중 처리하고 투사체를 제거한다. 한 틱에 경계를 지나쳐도 빠뜨리지 않는다. 화면 양옆 밖의 투사체는 명중시키지 않는다. 기존 게이지 비례 공격 점수 계산에 최소 공격량10을 적용해 최소50점을 보장한다. 기본 배율에서는 발사 시 게이지가60이면300점이다. 팝업은 실제 총점 증가량을 표시하고 짧은 시간 안의 여러 명중은 합쳐 보여준다.

### 4. 스턴과 명중 효과

명중 시1.2초 동안 오리의 상승·카메라·공격 준비 시간을 멈춘다. 기존에 발사된 불과 플레이어는 계속 움직인다. 정지 중 놓친 공격을 한꺼번에 발사하지 않으며, 스턴 종료 후 남은 시간부터 공격 예고를 이어간다. 여러 명중은 점수를 각각 주고 스턴은1.2초로 갱신한다(누적 합산하지 않음).

기존 파란물1첨벙이펙트와 코드로 그린 원형 충격파, 오리 흔들림, ‘수둔 명중! +점수’, 별3개, ‘오리 기절! 남은 초’, 시간 막대를 표시한다. splash 효과음을 명중 시 재사용한다. DuckStunSeconds와 WaterMinDamage 설정으로 조절할 수 있다.

## 2026-11-08 지속 상승 추격 업데이트 (최신 적용 기준)

### 1. 요청과 참고 영상

참고 영상 `화면 녹화 중 2026-11-08 152054.mp4`는 2분31.3초, 464×1010, 30fps의 다른 세로 스크롤 게임 영상이다. 화면이 계속 위로 이동하는 흐름을 참고했으며 Jumping Fish의 실제 오류 영상으로 해석하지 않았다. 사용자가 교체한 오리1/2/3 원본 PNG를 그대로 사용한다.

### 2. 오리와 화면 상승

### 3. 아이템과 협력

수둔·건사료 모두 물 안과 공중에 배치한다. 판마다 공중 배치 확률을30~70% 사이에서 뽑고 개별 위치도 무작위로 정한다. 실제 수량 비율은 표본에 따라 달라진다. 첫 두 아이템은 유효한 위치가 있으면 서로 다른 배치 종류가 된다. 공중 아이템은 물 위48~70세계단위에 놓고 다른 물과40, 다른 아이템과70세계단위 간격을 검사한다. 후속 플랫폼 생성으로 겹치면 원래 물 안으로 옮긴다. 공중 아이템은 점프·팔딱 비행 중 지나가야 먹을 수 있다.

자기 색 물의 진입 거부와 진입 시 색 변경 규칙은 유지한다. 먼저 올라간 사람이 색을 바꾸고 동료가 따라올 수 있다. 두 사람이 같은 물 안에 있을 때에는 색이 다시 바뀌어도 양쪽 모두 수영으로 게이지를 회복한다. 불리한 색 물에 혼자 머물면 기존처럼 게이지가 감소한다. 게이지가 있으면 물속에서 가만히 충전할 때 가라앉지 않으며, 게이지가 없으면 가라앉는다. 계속 상승하는 바닥 때문에 물에 오래 머무르는 것은 안전하지 않다.

현재 창 1024×720, 세계 폭 2068, 중력 300, 점프 높이 0.8m/포인트, 플랫폼 밀도 및 화면 전체 생성 색 비율은 유지한다. 수정기획서에 남아 있는 과거 4136폭·1920×1080·중력260·0.5m 수치로 되돌리지 않았다. 문서의 별도 제안인 점프 편향 단순화·새 패링키·공격 난도 변경·화면 밖 위험 안내는 추가하지 않았다.

## 3. 구현 내용

### 즉시 발동과 입력 분기

일반 점프 중 방향을 누르고 점프키를 새로 누르면 다음 물리 틱에서 속도를 교체하고 **그 틱부터 새 방향으로 이동**한다. 기존 상승·낙하·수평 관성을 더하지 않는다. 두 캐릭터 모두 상하좌우와 네 대각선을 지원하며, 대각선을 정규화해 속력을 같게 한다.

방향이 없을 때만 최대 0.30초 유예를 둔다. 방향이 들어오는 즉시 발동하며 유예 종료까지 기다리지 않는다. 키를 계속 누르거나 반복 입력해도 같은 입력을 재사용하지 않는다.

사용 자격과 방향이 있는 점프키는 팔딱 입력이 된다. 비용이 부족해도 같은 입력을 패링으로 바꾸지 않는다. 방향 없는 입력은 기존 패링을 열면서 방향 후보를 기다릴 수 있지만, 패링·피격으로 입력이 소비되면 후보를 취소한다. 블피 Enter 단독은 패링만 처리한다. 물속 충전과 기존 패링 도약 규칙은 유지한다.

### 직진과 종료

팔딱 속도는 `2 × sqrt(2 × Gravity × 팔딱비용 × JumpMetersPerPoint × PixelsPerMeter)`다. 현재 수치에서 점프40 → 팔딱20이면 약619.7세계단위/초이며, 장애물이 없는 0.18초 직진 거리는 약111.5세계단위다.

직진 중에는 중력·공중 가속·일반 수평 속도 제한·종전 부스트 감쇠를 적용하지 않는다. 새 방향 입력도 이미 선택한 직진 방향을 바꾸지 않는다. 직진 종료가 틱 중간에 오면 남은 시간에만 일반 물리를 적용한다. 마지막 속도를 유지한 상태에서 중력과 공중 조절을 재개하며, 상한220을 넘는 수평 속도는 초당600씩 줄인다. 반대 방향 입력은 추가 제동이 가능하다.

충돌·피격·아이템 획득·이동 거리별 소모는 계속 작동한다. 물은 이동 선분으로 진입 시각을 구하고 접촉 위치에서 이동을 끝낸다. 불은 물고기와 불의 상대 이동 선분, 아이템은 물고기 이동 선분으로 검사한다. 이미 오리 위험 경계에 있거나 물에 접촉한 상태에서 입력했다고 사망·입수를 취소하지 않는다. 벽에 막힌 수평 속도는 정지시키며 막힌 거리는 소모하지 않는다.

비용은 실제 일반 점프 비용의 절반, 한 일반 점프당1회다. 입수·자기 색 물 거부·사망·패링 도약에서는 후보 및 직진 상태를 초기화한다.

### 상태 표시

상단의 숫자 점수는 유지한다. 캐릭터 옆에 P1/P2, 충전 시 점프·팔딱 비용과 예상 잔여량 또는 부족량, 팔딱 가능·사용 완료·게이지 부족·방향 없음·추락 제한·물 진입 거부를 표시한다. 실패 문구는0.8초이고 직진 중에는 선택 방향 화살표를 표시한다. 두 캐릭터가 함께 출발할 때 안내가 겹치지 않도록 좌우와 높이를 나눴다.

## 5. 플레이 및 제출 확인

1. 원본 솔루션을 빌드해 F5로 실행한다. 기존 실행 중인 이전 빌드는 종료한다.
2. 일반 점프 후 방향을 먼저 누르고 점프키를 다시 눌러 수평·아래·대각선으로 즉시 꺾이는지 확인한다.
3. 방향 없는 점프키 입력 후0.30초 안에 방향을 넣는 경우와 비용 부족·사용 완료·물 거부 안내를 확인한다.
4. 래피 Space는 방향을 누른 공중 입력에서 팔딱이 우선이다. 블피 Enter는 패링 전용으로 유지한다.
5. 배경과 캐릭터 렌더링, WASD/방향키 이동, 실제 스피커의 BGM 출력을 학교 PC에서 확인한다.

교수님 제출 안내에 대한 현황: 배경은 BackgroundManager, 캐릭터는 GameMain/ResourceManager, 키보드는 GameMain 입력 수집과 GameWorld 물리, BGM은 AudioManager에 구현되어 있다. 리소스는 기존 images/sounds 구조를 유지하며 별도 목록 문서에 정리했다. 오디오 장치 관련 코드는 변경하지 않았다.

## 6. C# 학습 보고

실행 흐름: `Step()`의 상태 확인 → `BeginFlap/CaptureFlapDirection/ResolveFlap` → `TryFlap` → 직진 또는 일반 물리 → 이동 선분 충돌 → 입수·피격·사망 → 화면의 `FlapHint`.

- 벡터 정규화: 대각선의 속도가 더 커지지 않게 한다.
- 벡터 대입: 관성을 더하는 것과 전체 속도를 교체하는 것의 차이.
- `Math.Min`: 틱 중 직진에 사용할 시간과 일반 물리에 사용할 시간을 분리한다.
- `Math.Clamp`와 내적: 선분 위에서 가장 가까운 점을 계산한다.
- 상태 필드: `FlapPending`, `FlapUsed`, `FlapLockRemaining`의 서로 다른 역할.
- 정적 메서드와 문자열 보간: 게임 상태를 안내 문구로 변환한다.
- `using var`: 방향 화살표를 그리는 브러시를 자동 해제한다.

예상 출제 지점(실제 시험 범위 미확인): 속도 교체 전후 값, 대각선 정규화, 직진 종료 틱의 시간 배분, 같은 입력을 중복 소비하지 않는 분기, 점과 선분 사이 거리.

직접 재구현 과제: 현재 속도와 상한, 감속량, dt를 받아 상한 초과분만 서서히 감소시키는 메서드를 작성한다.
